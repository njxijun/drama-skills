# 血缘生成顺序

同一家庭的角色理应长得像一家人——父母定了轮廓，子女的锚点才有依据；不是每个角色
各自独立长出一套无关的脸。本文件只管**生成顺序与继承依据**，不创造剧情事实，也不
替代 creator acceptance。

## 血缘关系本身不是本技能的事实

谁是谁的父母、子女、兄弟，是剧情事实，权属在 `short-drama-develop`（故事引擎、人物
关系）或已接受剧本，不由资产环节推断或创造。本技能只做一件事：**已确认的血缘关系
一旦进入 设定集，就决定锚点生成的顺序和继承依据**；本技能不判断"这两个角色应不应该
是亲属"，那是叙事决定，问不到答案就走 `creator_decision_needed`，不要因为角色长相
接近就反推出未被确认的血缘。

反派身份与血缘重叠（例如反派其实是失散的至亲）同理：这类身份揲露何时让观众知道，
由 `short-drama-develop` 的 `audience-reveal.md` / `information_release` 决定；本技能只
按已确认的血缘写继承锚点，不因为要保守悬念就拒绝记录真实继承关系——记录的准确性
与观众何时看到是两件事，见下文"揭示前的锚点处理"。

## `lineage` 字段

Character 记录可选携带：

```json
{
  "character_id": "CHAR-XX",
  "lineage": {
    "parents": ["CHAR-FATHER", "CHAR-MOTHER"],
    "inherited_traits": [
      {"trait": "眼型", "from": "CHAR-FATHER", "note": "杏眼、上扬眼尾"},
      {"trait": "肤色基调", "from": "CHAR-MOTHER", "note": "偏冷白"}
    ],
    "divergent_traits": [
      {"trait": "发色", "note": "创作者指定为深棕，不随父母"}
    ]
  }
}
```

- `parents`：0、1 或 2 个已存在的 `character_id`；没有已知血亲就整节省略，不要填
  `"unknown"` 之类的占位符——省略字段本身就是"未声明血缘"的准确状态。
- `inherited_traits`：每条锚点写明继承自哪一位家长；不是"像父母"这种笼统断言，要
  具体到锚点层级（眼型、肤色基调、脸型轮廓等），能被下游图片提示词直接引用。
- `divergent_traits`：明确不继承、由创作者独立指定的锚点，避免下游把"没写继承"误
  当成"忘了继承"。

## 生成顺序：`structural_invariant`

**LIN-01**：若某 Character 的 `lineage.parents` 非空，其中每一个 parent 必须已经是
设定集里状态为 `accepted` 的 Character，才能把本角色的锚点提升为 `accepted`；
父母仍是 `draft` 或 `unresolved` 时，本角色的锚点只能停在同一状态，即使剧本已经
要求这个角色出场。**没有已接受的父母锚点，就没有可继承的依据**——这是可机械检查的
依赖顺序，不是创作偏好。

需要该角色先出场但父母锚点还没谈定时，两个选项都合法，创作者选：

1. 用不依赖继承的临时锚点（明确标 `provisional`）让该角色先能出现在分镜草稿里，
   父母定稿后再回来对齐、重新提交 `accepted`；
2. 先谈定父母的最小可识别锚点（不必是完整 Look，只要 Character 层的持久锚点），
   再生成子女——这是通常更快的路径，因为父母的锚点本来就要写。

不允许的做法：子女先定稿 `accepted`，父母后补时"看子女像什么样反推父母"——这会让
继承关系变成事后编造的巧合，而不是可追溯的依据。

## 怎么继承，不是复制粘贴

继承锚点不是把父/母的描述整段复制给子女，那样会做出双胞胎而不是亲属：

- 每条 `inherited_traits` 只搬一个具体锚点维度（眼型/肤色/脸型轮廓/体态），不是
  整张脸；
- 同一维度可以是"像父亲但弱化"或"介于两者之间"，写清楚偏向哪一方、偏多少，不要
  只写"像父亲"三个字——那对下游图片提示词没有可执行的信息；
- 非血缘但需要视觉关联的角色（继父母、养育关系）不适用本机制；那是关系锚点，不是
  外观继承，别为了"看起来像一家人"编造不存在的血缘。

## 揭示前的锚点处理

血缘关系本身待揭示（观众暂不知道）时，**设定集仍要准确记录真实继承关系**——资产
账本的准确性不能让位给悬念，否则真到揭示那一集，继承锚点从零现造，观众回看不出
线索，悬念变成了硬凹反转。

需要控制的是**图片提示词把继承锚点表达到多显眼**，那不是本技能的边界：
`short-drama-image-prompts` 在写参考图提示词时，可以选择只体现骨骼比例这类不易
察觉的相似、暂不体现痣位置发际线这类一眼可读的相似，等到揭示那一集再补全显性
特征。本技能只保证账本上的继承关系是真实、可追溯的；账本准确到什么程度对观众
可见，交给下游按揭示节奏决定。

## 与身份/变体规则的关系

`lineage` 是 Character 层的持久锚点补充，不是新的资产类型，仍然遵守
[identity-vs-variant.md](identity-vs-variant.md) 的复用/变体/新身份四分法；同一角色
换装换发型不改变 `lineage`，那仍是 Look 层的事。模板槽位不得覆盖 `lineage` 里已接受
的继承锚点，与"模板槽位不得覆盖身份锚点"（见 [character-and-look.md](character-and-look.md)）
是同一条规则的延伸。
